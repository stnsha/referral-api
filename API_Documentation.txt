                            AUTHENTICATION ENDPOINTS
===============================================================================

1. LOGIN / AUTHENTICATE
   Method: POST
   URL: /auth
   Headers:
     - Content-Type: application/json

   Request Body:
   {
     "staff_id": 2222,
     "staff_department_id": 20,
     "status_semasa": "Junior Audiologist",
     "outlet": [99, 100, 101],  // Optional: Array of outlet IDs (nullable for superadmin)
     "referral": 2              // Optional: Permission level (0=Normal User, 1=Superadmin, 2=Admin). Default: 2
   }

   Notes:
   - staff_department_id = 16 is reserved for superadmin (no business unit required)
   - outlet field is nullable for superadmin (staff_department_id = 16)
   - referral defaults to 2 (Admin) if not provided
   - See "ACCESS CONTROL & PERMISSIONS" section for details on permission levels
   - referral=0 (Normal users) are the MAIN users - they can create/update referrals
   - referral=0 users have read-only access for administrative features only

   Success Response (200):
   {
     "token": "eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9...",
     "expires_in": 86400
   }

   Error Responses:
   - 422 Validation Error:
     {
       "message": "The staff id field is required.",
       "errors": {
         "staff_id": ["The staff id field is required."]
       }
     }
   - 422 Invalid Department/Status:
     {
       "message": "Invalid department or status combination."
     }

===============================================================================
                        ACCESS CONTROL & PERMISSIONS
===============================================================================

PERMISSION LEVELS:
The API implements role-based access control with three permission levels
based on the "referral" field in the JWT payload:

1. NORMAL USER (referral = 0)
   - Can view data within their assigned outlets only
   - Can CREATE and UPDATE referrals for their assigned outlets
   - Has one or more assigned outlets (not limited to single outlet)
   - Read-only access for:
     * Forms and Form Details
     * External Referees and External Organizations
     * Report exports (can view but cannot export to CSV/Excel)
   - Cannot manage Business Units
   - Main users of the referral system

2. ADMIN (referral = 2) - DEFAULT
   - Can view data across all their assigned outlets
   - Full CRUD access for:
     * Referrals (all assigned outlets)
     * Forms and Form Details
     * External Referees and External Organizations
     * Report exports
   - Cannot manage Business Units (superadmin only)
   - Default permission level for administrative users

3. SUPERADMIN (referral = 1)
   - Full access to all business units and outlets
   - Can view ALL referrals from ALL outlets (no filtering)
   - Full CRUD access for all resources including Business Units
   - Can use staff_department_id = 16 (no business unit assignment required)
   - Bypasses all business unit and outlet restrictions

COMPLETE JWT PAYLOAD STRUCTURE:
{
  "iss": "app_url",                // Issuer
  "iat": 1234567890,                // Issued at (Unix timestamp)
  "exp": 1234654290,                // Expires at (Unix timestamp)
  "staff_id": 2222,                 // Staff identifier
  "business_unit_id": 1,            // Business unit ID (null for superadmin)
  "status_semasa": "Staff Title",   // Current staff status/role
  "outlet": [99, 100, 101],         // Array of accessible outlet IDs
  "referral": 2                     // Permission level (0, 1, or 2)
}

PERMISSION-BASED ERROR RESPONSES:

1. Read-Only Access Denied for Administrative Resources (403):
   {
     "message": "Unauthorized: Read-only access. Only admin and superadmin can create/update/delete."
   }

   Occurs when: Normal user (referral = 0) attempts to:
   - Create/update/delete Forms or Form Details
   - Create/update/delete External Referees or Organizations
   - Export reports to CSV/Excel

2. Superadmin-Only Access Denied (403):
   {
     "message": "Unauthorized: Only superadmin can create business units."
   }

   Occurs when: Normal user or Admin attempts to create/update/delete Business Units

3. Cross-Business Unit Access Denied (403):
   {
     "message": "Unauthorized: Cannot access resources from different business unit."
   }

   Occurs when: Non-superadmin attempts to access resources outside their business unit

4. Missing Business Unit (401):
   {
     "message": "Business unit ID not found in session."
   }

   Occurs when: Non-superadmin user has no business_unit_id in JWT payload

PERMISSION REQUIREMENTS BY RESOURCE TYPE:

- REFERRALS:
  * View: All users (filtered by assigned outlets)
  * Create/Update: All users (outlet-restricted)
  * Visibility difference:
    - Normal users (0): See only their assigned outlets
    - Admins (2): See all their assigned outlets
    - Superadmins (1): See ALL outlets

- FORMS & FORM DETAILS:
  * View: All users
  * Create/Update/Delete: Admin (2) and Superadmin (1) only

- EXTERNAL REFEREES & ORGANIZATIONS:
  * View: All users
  * Create/Update/Delete: Admin (2) and Superadmin (1) only

- REPORTS:
  * View: All users
  * Export to CSV/Excel: Admin (2) and Superadmin (1) only

- BUSINESS UNITS:
  * View: All users
  * Create/Update/Delete: Superadmin (1) only

// Sample PHP 5.3+ cURL implementation
function callAPI($method, $url, $data = array(), $token = null) {
    $curl = curl_init();

    $headers = array('Content-Type: application/json');
    if ($token) {
        $headers[] = 'Authorization: Bearer ' . $token;
    }

    curl_setopt_array($curl, array(
        CURLOPT_URL => 'http://your-domain.com/api' . $url,
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_HTTPHEADER => $headers,
        CURLOPT_CUSTOMREQUEST => $method
    ));

    if ($data) {
        curl_setopt($curl, CURLOPT_POSTFIELDS, json_encode($data));
    }

    $response = curl_exec($curl);
    $httpCode = curl_getinfo($curl, CURLINFO_HTTP_CODE);
    curl_close($curl);

    return array(
        'status_code' => $httpCode,
        'data' => json_decode($response, true)
    );
}

// Usage Examples:
// 1. Login
$loginData = array(
    'staff_id' => 2222,
    'staff_department_id' => 1,
    'status_semasa' => 'Junior Audiologist'
);
$result = callAPI('POST', '/auth', $loginData);

// 2. Get referrals (with token)
$token = $result['data']['token'];
$referrals = callAPI('GET', '/referral', array(), $token);

// 3. Create referral
$referralData = array(
    'business_units' => array(/* ... */),
    'referral' => array(/* ... */)
);
$newReferral = callAPI('POST', '/referral', $referralData, $token);

- 401 Unauthorized: Missing/invalid authentication
- 403 Forbidden: Valid auth but insufficient permissions
- 404 Not Found: Resource doesn't exist
- 422 Unprocessable Entity: Validation errors
- 500 Internal Server Error: Server-side errors

1. All JWT tokens expire after 24 hours (86400 seconds)
2. Business unit filtering is enforced on all protected endpoints
3. File uploads use base64 encoding in JSON requests
4. All protected endpoints require valid JWT token in Authorization header
5. Cross-business unit access is forbidden (403 error) for non-superadmin users
6. Validation errors return detailed field-specific messages
7. Referrals support external referees and multi-sequence workflows
8. Reports can be filtered by various criteria and exported as Excel
9. Form structures support dynamic field types (text, checkbox, radio, etc.)
10. Attachments are stored as base64 encoded strings in database

ACCESS CONTROL & PERMISSIONS:
11. Three permission levels: Normal User (0), Superadmin (1), Admin (2)
12. Normal users (referral=0) are the MAIN users - can create/update referrals for assigned outlets
13. Normal users (referral=0) have read-only access for administrative features:
    - Forms and Form Details (view only)
    - External Referees and Organizations (view only)
    - Reports (view only, cannot export to CSV/Excel)
    - Business Units (view only)
14. Admin users (referral=2) have full CRUD access within their business unit
    - Cannot manage Business Units (superadmin only)
    - Can export reports and manage all administrative resources
15. Superadmin users (referral=1) bypass all business unit and outlet filtering
    - Only superadmin can create/update/delete Business Units
    - Full access to all resources across all business units
16. Permission level defaults to 2 (Admin) for backwards compatibility
17. Superadmin can use staff_department_id=16 (no business unit required)
18. Outlet filtering differs by permission level:
    - Normal users (0): Can view/manage only their assigned outlets' referrals
    - Admin users (2): Can view/manage all their assigned outlets' referrals
    - Superadmin (1): Can view/manage ALL outlets (no filtering)
19. Normal users can have one or more assigned outlets (not limited to single outlet)
20. JWT payload includes "referral" field (0, 1, or 2) and "outlet" array
21. Business unit restrictions do not apply to superadmin (referral=1)
